Socket timeouts (commit 423bf8c + folded into 9d0ffe0):
- The 2026-11-09 15s SoTimeout was killing slow-link ops. Split by channel:
  JDBC URL `socket timeout=0` (no read ceiling on query/fetch; Cancel =
  Statement.cancel is the abort), connect/login loginTimeout=20s, CL/print
  clSystem SoTimeout 120s (spool list overrides to 300s around its op).
  Verified: 10,742 spooled files over a slow link in ~5s.
- Root cause (from JTOpen source): SpooledFileList uses the NP server LIST
  action over a data stream (chunked), NOT QUSLSPL/QGYOLSPL; SoTimeout is a
  per-read ceiling. The "user space size" error on *ALL-users is host-side
  (QNPSERVS backing store cap), surfaced via hostMessages already.
