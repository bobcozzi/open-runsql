## Spool read findings (JT400 NP server, for future IBMer interrogation)

- COZZI_W9 (*USERASCII, a real PDF payload): host refuses ALL reads —
  DSPSPLF on green screen: "cannot be displayed, copied or sent". Not JT400,
  not the bridge: QNPSERVR/host spool services reject the file's data
  (SPOOL(*NO) or ASP/authority/damage suspected — check file's ASP group vs
  session's, WRKREGINF QIBM_QSP_* exits).
- JT400 read internals (sources jar): open = OPEN action + retrieveNumberOfBytes
  (ATTR_PRECOMPUTE_NUMBYTES *YES auto-added); read() sends READ action with
  handle + ATTR_NUMBYTES; host RC != 0/EOF/incomplete lands in
  NPConversation.makeRequest default → ErrorCompletingRequestException(1=
  AS400_ERROR) — the real NP RC and any CPF message are dropped. cpCPFMsg_ on
  the stream impl held null/null for W9 (protocol-level refusal, no CPF).
- *AFPDS read works fine (getInputStream → raw AFP records, verified
  byte-level: 5A D3A8C6 BDT etc.). No JT400 AFP→PDF exists; CPYSPLF
  WSCST(*PDF) was built, worked, then REMOVED at user request (JT400-purist
  approach). 5770TS1 host transform remains the only real AFP→PDF route if
  ever revisited.
- QSPGETSP documents *SCS/*AFPDS/*AFPDSLINE/*LINE buffer behavior but never
  mentions *USERASCII → release/PTF-dependent server-side support.

## AFPDS image view (shipped late evening, commit 8a5d560 — user verified)

"View as images" on *AFPDS spooled files: bridge `format="image"` branch in
getSpooledFileData → `PrintParameterList` with `ATTR_MFGTYPE=*WSCST` +
`ATTR_WORKSTATION_CUST_OBJECT=/QSYS.LIB/QWPGIF.WSCST` →
`getPageInputStream(parms)` → per-page base64 GIFs (`contentType:
image/gif`, `pages[]`, `pageCount`). Frontend `viewSpooledImageFile` overlay
renders stacked `<img>` pages (cascade on multi-select, Esc/click-outside
close); context menu offers it when ALL selected files are *AFPDS;
double-click on AFPDS rows routes there too. Hosts without HPT/QWPGIF get a
structured `errorCode: imageTransformUnavailable` (no throw) → log line +
Download Raw fallback. No connect-time probing. Chose GIF over TIFF-G4:
browser-native, no JS TIFF decoder needed; QWPTIFFG4 +
getTransformedInputStream is the sharper fallback if overlays render chunky.

JT400 source facts (user had ~/Downloads/jtopen_11_2_source; structure verified
there, exact-version source is the 21.0.7 sources jar in ~/.m2):
- Open paths: plain getInputStream = OPEN + ATTR_PRECOMPUTE_NUMBYTES=*YES;
  getPageInputStream = OPEN_MODIFIED_SPLF + ATTR_PAGE_AT_A_TIME=*YES;
  getTransformedInputStream = OPEN_MODIFIED_SPLF + user parms only.
- CATCH GOTCHA: ErrorCompletingRequestException AND
  RequestNotSupportedException both subclass AS400Exception in JT400 21.0.7 —
  multi-catch listing them fails ("alternatives related by subclassing" /
  "already been caught"). One `catch (AS400Exception)` covers all three.
- New knob catalogued: ATTR_TGT_CODEPAGE (0x0108) on a transformed open
  triggers a second client-side ASCII conversion (EBCDIC CCSID → Cp437 etc.
  via a switch in PrintObjectTransformedInputStreamImplRemote). ATTR_SCS2ASCII
  (0x0071) exists but is a no-op for our files — nothing gates it
  client-side, server ignores it.
- WSCST availability assumption (user directive): QWPGIF/QWPTIFFG4 are
  IBM-supplied in QSYS with base OS print services; users will have all or
  none, and those without simply won't use the feature — degrade, don't probe.
